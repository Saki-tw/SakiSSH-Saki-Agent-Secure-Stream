## 🔴 AISec 提交稿 — 嚴重影響（最優先）

### 因 #16（完備性）需修改

| 行號 | 原文 | 直譯 | 修改方向 |
|:----:|------|------|----------|
| **L279** | `"Every possible agent action maps to exactly one of 6 responses (R1--R6). There is no undefined behavior."` | 每個可能的 agent 動作都精確映射到 6 種回應之一（R1~R6）。不存在未定義行為。 | 加 `"within the SASS evaluation pipeline"`（在 SASS 評估管線內） |
| **L336** | `L7: Watchdog → SIGKILL`（狀態機圖） | L7 看門狗 → 強制終止 | SIGKILL 標為 → R6 |
| **L345** | `"every node already handles it... converges to one of R1--R6"` | 每個節點都已處理…收斂至 R1~R6 之一 | 同步修正 |
| L36 | `"a 6-Response State Machine providing Total Response Mapping"` | 提供全回應映射的 6 回應狀態機 | 若 RFC 選 R6 子類型，此處不改 |
| L85 | `"a 6-Response State Machine with Total Response Mapping"` | 含全回應映射的 6 回應狀態機 | 同上 |
| L644 | `"a 6-Response State Machine with Total Response Mapping"` | 同上 | 同上 |

### 因 #2（認知挑戰）需修改

| 行號 | 原文 | 直譯 | 修改方向 |
|:----:|------|------|----------|
| **L36** | `"cognitive challenges (e.g., ChaCha20-Poly1305)"` | 認知挑戰（例如 ChaCha20-Poly1305） | ChaCha20 是計算性的不是認知性的。→ `"cryptographic channel-binding challenges"`（密碼學通道綁定挑戰） |
| L727 | `"prompt the user for re-authorization"` | 提示使用者重新授權 | 這才是真正的 cognitive challenge，保留 |

### 因 #19（EKM）需修改

| 行號 | 原文 | 直譯 | 修改方向 |
|:----:|------|------|----------|
| **L437** | `"v1.3: Eliminates 'session hijacking' via EKM... above-average loss"` | v1.3：透過 EKM 消除 session 劫持…高於平均的損失 | 加條件：限 Rust/Go 實作 |

### 因 #17（R1 零損失）需修改

| 行號 | 原文 | 直譯 | 修改方向 |
|:----:|------|------|----------|

## AISec 最高優先修改清單（6 項）

```
1. L279  — "no undefined behavior"（無未定義行為）→ 加 scope 限定
2. L336  — SIGKILL → R6 同步
3. L36   — "cognitive"（認知）→ "cryptographic channel-binding"（密碼學通道綁定）
4. L437  — EKM 證明加平台條件
5. L477  — "equivalent"（等效）→ "comparable"（可比較）
6. L388  — "zero data loss"（零資料損失）→ "zero filesystem data loss"（零檔案系統資料損失）
```

> [!IMPORTANT]
> 這 6 項在 RFC 修正後**必須同步修改**，否則 AISec reviewer 會在同一份論文裡找到 RFC 已修正的矛盾。
